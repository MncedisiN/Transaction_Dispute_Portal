# Assessment messaging settings

messaging.json contains the owner's testing Infobip settings and is deliberately included for this controlled repository handoff. Anyone who can read the repository can read those credentials. Do not publish this repository publicly or reuse these keys for production.

The Docker build context excludes this entire directory. Compose mounts it read-only into the initializer, which copies only the supported messaging options into the API's generated private runtime settings. Database passwords, service identities, Data Protection keys, OTP hash keys and balances are not copied from the owner's development environment.

The API receives a new installation-specific OTP hash key. Provider keys and sender approval remain controlled by Infobip. The Compose default leaves external messaging disabled. This submission now explicitly enables it with EXTERNAL_MESSAGES_ENABLED=true in the root .env file after testing the configured email and SMS channels. This submission also sets REQUIRE_CONTACT_VERIFICATION=true, so registration requires a real code. Password-only administrator/customer sign-in remains enabled; login two-factor authentication is off. Existing unverified contacts stay unverified until their owners confirm a code. There is no fixed verification code or shared default password. Production rejects the assessment bypass.
